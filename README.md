# 打野判断力 · 限时决策训练

一个用来练《王者荣耀》打野**判断力**的网页小游戏。

一屏一个打野情景——开局被反野、河蟹该不该抢、对面打野在下路你要去哪一路——
**在几秒内从 4 个选项里选出最优解**，选完立刻告诉你：每个选项为什么对、为什么错。

> 这个项目唯一的核心主张：**打野的差距不在操作，在于"在正确的时间做正确的事"。**
> 而这件事是可以在浏览器里一道道练出来的。

## 和「算期望值」的区别

市面上不少打野训练器会把每个选项的收益标在按钮上（`+128 金币`）。那样游戏就变成了**算术题**——
你会去算哪个数字大，而不是练判断。

这个项目故意**不显示任何数值**。你看到的是四个平铺的动作，必须在几秒内凭判断选。
因为真实对局里没有数值提示，也没有无限时间。

## 玩法

1. 选限时（12s / 8s / 6s / 不限时）和题量，点「开始训练」。
2. 每题给你一段处境：小地图 + 文字描述。**描述从上到下就是按重要性写的。**
3. 在倒计时结束前点一个选项（键盘 `1`~`4`）。
4. 答完立刻出判定：

   | 标记 | 含义 |
   | --- | --- |
   | **最优解** | 这道题该做的事，+100 分起，越快答对拿的时间奖励越高 |
   | **可行** | 不算错，但不是最优，+40 分 |
   | **失误** | 这一手会亏节奏，0 分 |

   四个选项**全部**会被标上判定，并附上详细解释——所以你答错的时候，才是真正学到东西的时候。
5. 全部答完给一份复盘报告：各类情境的准确率、你最弱的一类、以及针对性的下一步建议。
   下方还有可展开的**错题复盘**。

### 做题时的正确心态

别想"哪个收益高"，想 **"我现在知道什么信息、我该拿这个信息做什么"**。

这是打野所有决策的共同内核：

- 对面打野**位置已知** → 你该利用它做事（反野 / 抓另一路 / 开龙）
- 对面打野**失联** → 你该先获取信息，而不是赌
- 少人 / 残血 → 你该做的是**止损**，不是找机会

## 题库

24 道情景题，覆盖 7 类：

| 类别 | 数量 | 练的是什么 |
| --- | --- | --- |
| 开局 | 3 | 面对强势打野怎么安全开局、队友送一血之后怎么办 |
| 节奏 | 5 | 河蟹取舍、回城时机、暴君前置、用时间做交换 |
| Gank | 3 | 兵线位置、越塔风险、绕后 vs 正面 |
| 反野 | 3 | 情报比操作重要、什么时候该放弃 |
| 资源 | 4 | 开龙的前提条件、逆风止损、以龙换龙 |
| 团战 | 4 | 进场时机、打野是"第二个进场点" |
| 逃生 | 2 | 残血时的目标只有一个：活下来 |

每道题的每个选项都写了「为什么」，这让题库本身就可以当一份**打野决策手册**来读。

## 两个刻意的工程设计

**1. 选项顺序在渲染时随机打乱。**

题库里最优解的原始位置本来就容易集中在前面几项。如果不打乱，玩家很快会发现
"闭着眼睛总选 A 或 B 就能拿高分"——这个训练器就废了。

所以每题渲染时都会 `shuffle()` 一次选项顺序，作答和复盘都沿用这同一份顺序。
`tools/check.mjs` 里有一条专门的断言盯着这个机制：一旦有人把打乱逻辑删掉，
自检会立刻报错。

**2. 内容本身要被校验。**

这个项目的"内容"就是产品。题库写错了，玩家学到的就是错的。所以自检不只是查语法和 DOM，
还会把题库解析出来逐条验证：

- 每道题恰好 4 个选项
- 每道题**恰好有 1 个**最优解（`v === 2`）
- 分值只用 0 / 1 / 2
- 每个选项的解释都不少于 25 字（防止写出"回城吧"这种没信息量的解释）
- 7 个类别全部有覆盖
- 选项文案里不许出现金币/分数数值（那是本项目的设计前提）

## 自检与行为验证

### 静态自检

```bash
node tools/check.mjs        # 语法 / DOM / 题库内容
```

三层验证加起来才够：静态检查管「写没写对」，模拟器管「逻辑跑不跑得通」，
布局探针管「用户看不看得见」。

当前状态：

```
  ✓ 存在内联脚本  (1 个)
  ✓ 内联脚本语法有效
  ✓ 所有必需的 DOM id 都存在
  ✓ byId 引用的 id 全部有对应元素
  ✓ 题库可以被解析  (24 道题)
  ✓ 题库规模足够（>=20 道）  24 道
  ✓ 每道题的 cat 都是已知类型
  ✓ 每道题恰好 4 个选项
  ✓ 每道题恰好有 1 个最优解(v=2)

### 行为验证（无头模拟器）

静态检查证明不了「游戏真的能玩」。`tools/sim.mjs` 会把内联脚本抽出来，
注入最小 DOM 桩后**真的点按钮、真的答题、真的读复盘报告**：

```bash
node tools/sim.mjs 200      # 跑 200 局
```

它验证的最关键一条是**位置偏好**——如果玩家闭着眼睛总选第一个选项就能拿高分，
说明选项打乱没生效、这个训练器就废了：

```
【位置偏好检验】
  ✓ 最优解在 4 个位置上分布均匀（打乱生效）  A/B/C/D = 25.0% / 25.3% / 23.9% / 25.9%
  ✓ 「无脑总选第一个」拿不到高分（≈25%，即随机水平）  最优率 25.0%

【策略对照】
  ✓ 选最优解的玩家命中 100% 最优  最优率 100.0%
  ✓ 随机乱选的玩家 ≈25%（与「总选第一个」同档）  最优率 24.9%
  ✓ 满分玩家得分显著高于随机玩家  满分 4700 vs 随机 960

【倒计时 / 超时】
  ✓ 超时会自动结算并允许继续  超时 10 题，得分 0
  ✓ 同样反应速度下，限时越短时间奖励越少  6s 限时得分 4100 < 12s 限时得分 4412
  ✓ 限时相同下，答得越快奖励越高  快答 4652 > 慢答 4100
```

模拟器用的是固定种子的随机数，所以结果是可复现的，不会偶发飘红。

### 布局探针（真实浏览器测量）

前面两个工具都发现不了「CSS 写错导致元素根本不显示」。`tools/probe.mjs` 用无头
Edge / Chrome 打开页面，让页面自己测量关键元素的几何尺寸，再逐条断言：

```bash
node tools/probe.mjs
```

它在开发时抓到了一个真实 bug：报告页分类进度条的 `.fill` 是行内 `<span>`，
而**行内元素上的 `width` / `height` 会被浏览器直接忽略**，于是所有进度条宽度都是 0。
逻辑完全正常、模拟器全绿，但用户什么都看不到。

找不到 Edge / Chrome 时会自动跳过，不影响其它检查。

## 本地运行

单文件网页，直接双击 `index.html` 即可，不需要构建或服务器。

## 部署

静态站点，通过 GitHub Pages 发布。仓库根目录下的 `index.html` 就是入口。
`tools/publish.mjs` 用 GitHub REST API 把文件推到仓库并开启 Pages（无需本地安装 git）。

```bash
node tools/publish.mjs
```

Token 从环境变量 `GH_TOKEN` 读，或放在工作区的 `_token.txt`（已在 `.gitignore` 中排除）。

> **如果报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`**：说明本机装了 Node 默认不信任的根证书
> （公司网络 / 代理 / 杀毒软件都常见）。用系统证书库重跑即可：
>
> ```bash
> node --use-system-ca tools/publish.mjs
> ```
>
> 脚本开头有预检，遇到这个情况会直接提示，不会只丢一堆堆栈给你。

## 怎么继续加题

在 `index.html` 的 `BANK` 数组里追加一条即可，不用改任何逻辑：

```js
{
  cat:'反野', t:'7:30', q:'标题', d:'处境描述',
  m:[[76,42,'neutral','对面蓝buff']],       // 小地图标记（可省略）
  opts:[
    {t:'选项文字', v:0, why:'为什么这个选项是失误'},
    {t:'选项文字', v:2, why:'为什么这是最优解'},
    {t:'选项文字', v:1, why:'为什么可行但不最优'},
    {t:'选项文字', v:1, why:'…'}
  ]
}
```

加完跑一次 `node tools/check.mjs`，它会告诉你有没有漏写解释、有没有两个最优解。
不用手动调整选项顺序——渲染时会自动打乱。

小地图坐标是 `0~100` 的示意坐标系：蓝方基地在左下 `(10,90)`，红方基地在右上 `(90,10)`，
河道沿 `y = x` 对角线，主宰在 `(35,35)`、暴君在 `(68,68)`。
